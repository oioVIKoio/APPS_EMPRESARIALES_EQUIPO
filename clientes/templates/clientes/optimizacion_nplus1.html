select_related() genera un JOIN SQL que carga clientes_favorito + clientes_cliente + catalogo_producto en una sola consulta.

📚 select_related() vs prefetch_related()

select_related()
  • ✅ Para relaciones 1:1 y N:1 (ForeignKey)
  • ✅ Usa JOIN SQL (una consulta)
  • ✅ Ejemplo: select_related('cliente', 'producto')
  • ⚠️ No funciona con ManyToManyField
prefetch_related()
  • ✅ Para relaciones M:N (ManyToManyField)
  • ✅ Ejecuta 2 consultas (separate query)
  • ✅ Ejemplo: prefetch_related('categorias')
  • ✅ También funciona con ForeignKey

🛠️ Ejemplos prácticos de optimización

# ❌ Sin optimizar (N+1 queries)
direcciones = Direccion.objects.all()
for dir in direcciones:
    print(dir.cliente.nombre)  # Query por cada dirección

# ✅ Con select_related (1 query con JOIN)
direcciones = Direccion.objects.select_related('cliente').all()
for dir in direcciones:
    print(dir.cliente.nombre)  # Sin queries adicionales

# ❌ Sin optimizar (N+1 queries)
favoritos = Favorito.objects.all()
for fav in favoritos:
    print(fav.cliente.nombre, fav.producto.nombre)

# ✅ Con select_related (1 query con JOIN)
favoritos = Favorito.objects.select_related('cliente', 'producto').all()
for fav in favoritos:
    print(fav.cliente.nombre, fav.producto.nombre)  # Sin queries

# ✅ select_related con doble JOIN
cliente = Cliente.objects.select_related('perfil', 'direccion__ciudad').get(pk=1)
# Una sola consulta: clientes + clientes_perfil + clientes_direccion + ciudades

# ✅ prefetch_related para M:N
cliente = Cliente.objects.prefetch_related('favoritos__producto').get(pk=1)
# Dos consultas: clientes + (favoritos + productos JOIN)
